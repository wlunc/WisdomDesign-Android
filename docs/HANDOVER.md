## 2. 怎么读（按角色）

### 第一天接手（约 40 分钟）

1. [`../AGENTS.md`](../AGENTS.md) §0–§2 —— 现状（`apiCheck` 红、门禁哪些还没落地）、不能做什么；
2. [`DEV-PLAN.md`](DEV-PLAN.md) **§1 本端定位** —— 本端负责 37 件里哪些、不属本端的是什么；
3. [`DEV-PLAN.md`](DEV-PLAN.md) **§2 M0 本端视图** —— 当前里程碑任务、入口判据、出口判据，含 **§2.1.1 `apiCheck` 由红转绿的 A1+A3 六步**；

5. 需要动手时再读 **§13 SOP**（8 步）。

### 要开工一个组件（约 15 分钟）

1. `DEV-PLAN.md` **§12.1** 找到该件（批次 / 关键路径件 / 落点 / `SPEC.md` 锚点 / C-15 名 / 验收代码 A·S·C·E·V·L / 依赖）；
2. `DEV-PLAN.md` **§19.2** 查它的**设计编号**与画廊检索词 → 打开设计规格与画廊；
3. `DEV-PLAN.md` **§19.4** 看它的**尺寸 / 变体 / 状态 / 关键令牌**速查；
4. **M2 的 11 件**再过一遍 **§20.5「实现前自检十问」**（答不出就先别写）；
5. `SPEC.md` 对应节 —— 签名与断言的真源；
6. 走 **§13 SOP** 的八步（含 `apiDump` 同提交）。

### 要结批

`DEV-PLAN.md` **§14 验收手册**（逐批：出口判据 + 可运行命令 + 不通过处置 + 勾选清单）+ **§3 批次分配**（批前签名冻结与出口）。

## 7. 三条 Android 特有的"容易踩"

1. **公开面不得出现 m3 类型**（G9）——一旦泄漏进公开签名，`apiDump` 不会红但契约已破；用 `m3 import 计数 == 1`（G1-③）与人工判据双查。
2. **`apiDump` 必须与成因同提交**——符号快照跨提交漂移会让 `apiCheck` 变成噪声。
3. **rebase merge，禁 squash**——跨层移动与语义变化必须保留为两个提交，否则 ABI 评审无法回溯。
